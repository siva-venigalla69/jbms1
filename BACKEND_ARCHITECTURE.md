## Architecture Type

### Serverless / Backend-as-a-Service (BaaS)

This system uses **Supabase**, which is a complete Backend-as-a-Service platform.

#### Traditional Architecture (You DON'T have this):
```
Browser → API Server (Express/Node.js) → Database
         ↑
    You manage this!
```

#### Your Architecture (Serverless):
```
Browser → Supabase APIs → Supabase Database
         ↑
   Managed by Supabase!
```

### What This Means

✅ **Advantages**:
- No server setup or maintenance
- Auto-scaling (handles 10 or 10,000 users automatically)
- Built-in authentication
- Automatic API generation
- Real-time capabilities
- Automatic backups

❌ **Limitations**:
- Less control over custom business logic
- Dependent on Supabase platform
- Complex operations need database functions

**Frontend Access**:

## Data Flow

### Complete Request Flow

#### Example: Creating a New Order

```
1. User fills form in OrderPage.tsx
      ↓
2. Component calls ordersApi.create({ ... })
      ↓
3. simplifiedApi.ts validates and formats data
      ↓
4. Calls supabase.from('orders').insert({ ... })
      ↓
5. Request sent to Supabase REST API
      ↓
6. Supabase validates auth token (JWT)
      ↓
7. Supabase checks RLS policies
      ↓
8. PostgreSQL inserts data
      ↓
9. Database trigger generates order_number
      ↓
10. Response sent back through chain
      ↓
11. Component updates UI
```

### Authentication Flow

```
1. User enters email/password on Login.tsx
      ↓
2. AuthContext calls supabase.auth.signInWithPassword()
      ↓
3. Supabase Auth validates credentials
      ↓
4. Returns JWT access token + refresh token
      ↓
5. Frontend stores token in localStorage
      ↓
6. All subsequent requests include token in header
      ↓
7. Supabase validates token on each request
```

## Security

### Row Level Security (RLS)

**Status**: ✅ Enabled on all tables

RLS ensures users can only access data they're allowed to see, even if they have the API key.

**Example Policy** (should be created):
```sql
-- Users can only see their own orders
CREATE POLICY "Users see own orders"
ON orders FOR SELECT
USING (auth.uid() = created_by_user_id);

-- Admins see all orders
CREATE POLICY "Admins see all orders"
ON orders FOR SELECT
USING (
  EXISTS (
    SELECT 1 FROM users
    WHERE id = auth.uid()
    AND role = 'admin'
  )
);
```

### API Security

1. **Authentication**: All requests include JWT token
2. **RLS Policies**: Database-level access control
3. **HTTPS**: All traffic encrypted
4. **CORS**: Configured allowed origins
5. **Rate Limiting**: Supabase handles automatically
